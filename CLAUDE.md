# Working on Peras

Read at the start of every session. It holds the rules of the project and the traps already fallen into, so that they are not fallen into again. When a new trap is found, add it here the same day, and add the finding to [docs/en/findings.md](docs/en/findings.md) and its French translation.

## The project's rules

- **Report to the owner in French.** Docs are written in English first, then in French; `node scripts/check-i18n.mjs` checks that every page exists in both.
- **No dependency on another language than Rust**, not even in a benchmark. A competitor that needs an npm package or a C library is cited from its published figures, never installed.
- **A build fails on any error.** Before a commit: `cargo fmt`, `cargo clippy -D warnings`, the same two for `fuzz/` (`--manifest-path fuzz/Cargo.toml`, a workspace of its own, M014), `cargo test --workspace`, `pnpm run check` (format, lint, types, tests, translations, Markdown links, `pnpm audit` with no vulnerability), `pnpm run docs`, and the `--check` of each benchmark touched. Every commit, a commit of documentation alone included: a page changes what the docs tests compile (M021).
- **pnpm installs nothing published less than 24 hours ago** (`minimumReleaseAge`); never add an exclusion.
- **Commits** follow Conventional Commits, signed off (`git commit -s`), with no attribution line nor footer naming an assistant, commit or pull request (the owner, 2026-11-25). No model name in the repository. **A pull request's title** follows them too: the CI checks it (`conventional-title`), the local checks do not (M021).
- **Commits are authored by the owner**, who decides and signs off: in this repository, `git config user.name "Artkabis"` and `git config user.email "8205827+artkabis@users.noreply.github.com"`, set before the first commit of a session.
- **No force push.** After a pull request is merged, merge `main` into the branch.
- **Nothing published outside the repository** (forums, social networks) without the owner.
- **Performance is shown scientifically, with a touch of poetry** (the owner, 2026-11-24), as the garden of Apeiron (decision 0013): a measure that matters is also a scene, the same journey for each option, the figures beneath it; the poetry shows what the probes measure and never decides.
- **Every decision is an improvement, never a regression** (asked by the owner on 2026-11-17). Before a decision lands, `node scripts/check-regression.mjs <the commit before it>`: every module of the benchmarks and examples built by both compilers is identical or smaller, none larger; a program that chooses what the decision brings may grow by what the decision measures and records, one that does not stays identical (the owner, 2026-11-24, M038); the compiler is no slower (median ratio at most 1.05); its size is reported, and grows only by what the decision brings. An option measured and not chosen is removed from the compiler once the decision lands, its figures kept in the decision and its code in git (r2 of decision 0032 cost every build 90 KB). A module that changes is measured by the decision's own A/B.
- **A decision compares its options by measure, not by reasoning alone** (asked by the owner on 2026-11-16). Before choosing, each serious option, the ones under "Not chosen" included, is built as a prototype where it can be, and compared on four things, registered before any measure (M003): speed (time of the operation, A/B in one process, M017), CPU load (time a core is kept busy, as decision 0012 measures it), memory and bytes shipped, and ease of writing (the same program written for each option: lines, notions to learn, errors met). An option that cannot be built is said so, with why, never ranked by a guess (M001).

## The environment

- Node: `export PATH=$(ls -d /opt/node*/bin | tail -1):$PATH`.
- Chromium: never `playwright install`; set `PERAS_CHROMIUM=/opt/pw-browsers/chromium`, or `executablePath` in a script.
- A script that imports the repository's packages runs from the repository, not from the scratchpad.
- The CI installs browsers through `scripts/install-browser.mjs`, which needs the browser's download and only tries its system packages: a job red at `Failed to install browsers` is the runner's network, not the code; read the log before saying which (F107).
- A linker that dies on `signal 7 [Bus error]` means a full disk: `df -h .`, then remove `target/debug` (M023).
- A filter on the output of `cargo test` keeps `^error` lines: a test that does not compile prints no failed result (M023).
- `pnpm audit` ignores only what `auditConfig.ignoreGhsas` in `pnpm-workspace.yaml` lists, each entry decided by the owner with the condition to remove it: GHSA-fc5q-39xc-vjpf (picomatch, development tools only, no patched version on 2026-11-17) goes once a patched picomatch is 24 hours old.
- GitHub Pages is enabled: `docs.yml` deploys the site from `main` at each merge, `/playground/`, `/stream/` and `/observatory/` with it. This container cannot reach `github.io`: read the workflow's run before saying a page is online (M005).

## Studies: the traps already fallen into

Each line is a finding of [docs/en/findings.md](docs/en/findings.md).

- **Read the code before a design says what the compiler does**: a step planned on a cost not read (M019), a decision that claimed a pass that does not exist (M020).
- **Register the protocol before any measure**, and test its definitions against a first version before registering: two rules that disagree are found by code, not by reading (M003).
- **A value that could not be measured makes a verdict undetermined**, never a hypothesis that holds (M001).
- **Check every competitor against the rules of the project** before naming it in a protocol (M004).
- **Count alike**: what is left out of one version's count is left out of every version's (M006).
- **Name the build of every version a protocol measures**, and pass it explicitly: decision 0029 compared a debug managed module with TypeScript, 4.04 times its time where production gives 2.62 (M029).
- **Compare runs by their ratios, never by their milliseconds**: a new session may get another processor; read the machine in each `results.json` (M016).
- **Decide a change by an A/B in one process, not by two profiles**: the machine drifts within a session; `node scripts/ab-data.mjs <ref>` alternates both compilers and takes the ratio round by round (M017).
- **`pnpm run check` is the last command before a commit**, after every build and test: a build rewrites the files it generates (M012).
- **A failing check stops the commit**: chain the checks and the commit with `&&`, never print exit codes and commit in the same line; export `PERAS_CHROMIUM` in every command that runs a check in a browser (M028).
- **A check filtered by `grep` must still stop the commit**: a pipeline's status is its last command's; run the checks under `set -euo pipefail`, never `cargo clippy … | grep …;` (M030). Nor the whole script behind a pipe, `checks.sh | tail`: its status is then `tail`'s; write its output to a file and its status after it, and commit only on `exit 0` and `all checks pass` (M031).
- **Commit only on the log's last lines read exactly**: `tail -n 2 log | head -1 | grep -qx "all checks pass" && tail -n 1 log | grep -qx "exit 0" && git commit …`, never on `tail` of the log, which succeeds whatever it says; run the script as `bash checks.sh` (M033: a script that lost its right to run committed nothing checked).
- **`check-regression` takes an option as an argument**, `node scripts/check-regression.mjs <ref> PERAS_PROTO_X=v`: it unsets every `PERAS_PROTO_*` of its environment, and one given there measures nothing; read the first line of its report, which names the options (M039).
- **A decision lands in the READMEs too**: linked from `README.md` and `README.fr.md`, its benchmark named in both bench READMEs, and the status of `README.md` said again when it changes what Peras can do; `pnpm run check` fails otherwise (`scripts/check-readme.mjs`, M040).
- **Measure an option's floor before building it** (the owner, 2026-11-25, M041): a program written by hand with the layout and the work the option would have the compiler produce gives its least cost in minutes; when that floor already fails the criteria, the option is not built, and the decision records the floor as its measure. Arenas and pools failed on a memory their layout showed before any prototype.
- **Measure the noise in every protocol** (M042): an A/A control, a module timed against itself in the same rounds, and the compiler's time measured twice; a threshold inside that noise decides nothing, and the protocol says so. A module identical to the reference gave 1.025, and p1's compiler 1.025 then 1.056 for the same code.
- **Two changes made together are measured apart** (M043): each alone and both, when an option combines them; p4's check made once and its walk without an array were not, so neither can be credited with its gain (M013).
- **A protocol bounds memory as a ratio and in bytes**, at most 1.10 times or one page of 64 KiB more, and counts a module identical to the reference's at 1.000: a ratio alone made a fixed cost five times a one-page program's memory, and noise failed an identical module (M037).
- **Format, lint and commit before a measure**, so that the run is at a known commit; a run started on code that changes afterwards is stopped and run again (M002).
- **Nothing that uses the processor during a measure**: no build, no test. Write, read, plan. And nothing written in the repository while the checks run: they would check a tree that is no commit; write in the scratchpad (M032).
- **A build that reuses a cache must prove it rebuilt what changed.** Old sources extracted with their commit dates look older than the cache and are not recompiled; extract them dated now, or give each its own target (M009).
- **A flawed run is kept with its flaw**, archived, and its correction listed as a departure from the protocol.
- **Never say a thing is online, deployed or passing before seeing it**: read the workflow's run, not the workflow's file (M005).
- **A cancelled job is a failure, and a test is timed in the debug build the CI runs**: the Rust job stops at 20 minutes, and one test of 2,000,000 pairs took all of it unnoticed (M022).
- **A step of a plan meets the plan's criteria too**: before saying it landed, read the criteria of the decision that orders it, not only its own; decision 0021's roadmap was missed three times (M025).
- **"All checks pass" means the CI of the last commit, read on GitHub**, and locally every `--check` script of `scripts/`, not only those of the files touched: a change of defaults breaks the scripts that relied on them (M007).

## Code: the traps already fallen into

- **No bug is left aside** (the owner, 2026-11-25): every bug found, even beside other work, is recorded the same day as a finding with its reduced case, then fixed with a test that failed before; a bug that cannot be fixed at once stays an open finding, and the work under way names it (F119, F120).

- **A lowering never drops a statement in silence**: a path it cannot build reports E0900. A write through an `Rc` returned with nothing written and nothing said, `w()` gave 3 (F016); then a step and a field of an `Rc` an element holds (F018). When a new kind of place is added, read every `else { return; }` of the paths that write: assignment, step, element, method.
- **A script that writes text goes in a quoted heredoc** (`<<'EOF'`), never `<<EOF`: unquoted, the shell runs each `` `…` `` of the text as a command and writes what it prints; two lines of the roadmap lost their code that way, `.apeiron` and `parallel for` gone (M044).
- **Edit by exact, unique replacements.** Never replace a slice between two markers: one script deleted every function between `keep_before` and the end of a file. After a scripted edit, `git diff --stat` and a build.
- **The release verifier is right until proven otherwise.** When it refuses code, reduce the case to a few lines, add it as a test that fails, then fix the lowering (F001, F002).
- **A test that passes here and fails in CI is a race until proven otherwise.** Reproduce it by changing the timing (a smaller or larger workload), trace the messages, and make the code wait for an explicit signal rather than raising a timeout (F106).
- **Profile by removing, not by guessing.** A profile that adds steps one at a time can blame the step added when the cost is in what it forces (F201: `parseI32` blamed, the copies of a stored `split` guilty). Compare variants that differ by one thing, and check that an optimization is taken before crediting it with a gain. A variant that removes a step and its calls together blames the step for the calls' cost (M013).
- **The end-to-end tests use `target/release/perasc`**: `cargo build --release -p perasc` before `pnpm run e2e`, or they test the compiler as it was (M018).
- **A round trip can hide a difference**: a test that compares what a module gives back passes through the loader both ways; compare what the module computes from each input too (F217).
- **A mutation must reach what it tests** (M024): a change of the lowering alone does nothing where the checker decides, and a change of both is caught by the checker first. Put the mutation where the rule is, and see the test fail. A mutation that passes is first a gap in the tests: widen the program until it reaches the rule; doing so found a bug (M027, F013).
- **The differential test sees the passes after lowering, not lowering itself** (M026): its oracle is the lowered IR, interpreted. A mutation of the lowering passes it; one of the generator or of the interpreter fails it. What lowering computes is held by the end-to-end tests against the managed module.
- **An optimization passes the differential test before it lands** (`crates/perasc-driver/tests/differential.rs`): once with `PERAS_DIFFERENTIAL_SEEDS=2000`, and once with the optimization broken on purpose, to see the test fail (M015). Extend its generator with what the optimization touches.
- **A prototype of the runtime is tested with its own runtime, and twice**: the differential test linked TLSF as it is, and ran nothing of decision 0043's arena (M034); a prototype that keeps state between calls is called twice on one instance, with a program that reaches that state, and compared with the reference (M035).
- **A new operation or element type is looked for wherever its neighbours are matched**: `grep` every `BinOp::Div`, every `Elem::`, every size the runtime tests. An unsigned division was taken for one that cannot stop the program (F008), bytes for lanes of four (F007), and `reverse()` knew no element of two bytes (F009).
- **Write Peras as a user would before claiming what it can do.** The frictions found that way go to the findings, with the diagnostic as evidence.

## Peras as it is today

What a program can rely on, and what it cannot yet; the details and their evidence are in the findings and in [the status](docs/en/reference/status.md).

- `Option`: `isSome()`, `isNone()`, `unwrapOr(x)` (evaluates `x` only when there is no value, in both modes, as `??`: decision 0028, F012), and `?`. After `if (x.isNone())` whose block leaves, and in the block of `if (x.isSome())`, a `const` or a parameter `x` is its value, and so is a field of one, `child.parent` (decision 0028, F115); the tests combine as in TypeScript, through `&&`, `||`, `!`, `else` and `while`, `if (p.isNone() || !alive[p]) { break; }` (decision 0045, n2; `Checker::facts`, `PERAS_PROTO_NARROW=n0` the compiler before it, for `scripts/bench-narrow.mjs` only); where its option is expected, it is the option (F114); a `let` is not narrowed. No `unwrap`, no `let … else`; a `match` whose arm leaves a loop gives no value (F101). A move into a call happens once every argument is evaluated: `m.set(key, m.get(key).unwrapOr(0) + 1)` builds (F103). `PERAS_PROTO_MOVE`, `PERAS_PROTO_TAKE` and `PERAS_PROTO_FALLBACK` build the other options measured, `before` the compiler before it, for `scripts/bench-options.mjs` only.
- Structures have `copy()` (F102), unless they hold a resource, a JavaScript value or a function. A field moves out of a structure the function owns, `const c = row.country;`; the rest stays usable (decision 0025).
- Functions are values in both modes: `(i32) => i32` wherever a type is, copied freely; arguments lent; not across to JavaScript (decision 0025). In an owned module, an arrow function used as a value captures numbers and booleans, copied when it is made (decision 0026), and strings, arrays, maps, sets and function values, lent when the closure cannot escape, copied otherwise: the ownership pass decides (`Analysis::escaping`, decision 0027). A `let` or `inout` captured is E0251. `PERAS_PROTO_CLOSURE` builds the other options measured, for `scripts/bench-closures.mjs` only. A function value is a counted environment, static when it captures nothing; the table's functions take it last.
- Modules: a `.peras` file imports functions, structures and enumerations of other `.peras` files, compiled into one module; not generics, not the methods of an imported structure, no `as`, no cycle (decision 0022).
- Module variables (`let` at the top of a `.peras`): numbers, booleans, and structures, enumerations and options of them, a constant initial value; not strings or arrays, not `inout`, not in a `parallel for` (decision 0023).
- `parallel for`: a turn calls only functions that change nothing (no allocation, no element or module variable written, no function value), and writes its index or its parts, `let band = xs.part(i, k)` (decision 0031); no allocation, no reduction in a turn (F301). The loader splits a loop of heavy turns, a loop or a call in a turn, from two turns, others from 256. `PERAS_PROTO_PAR` builds the other options measured, for `scripts/bench-parallel.mjs` only.
- Numbers: a literal takes the type it is used as, `2 * x` on a float, `[1, s, 0]` (decision 0030; E0211 retired); a variable is never converted, `n * x` with `n` an `i32` needs `n.toF64()` (E0210). `i / n` on integers is an integer division; where its quotient meets a float, E0210 shows the division and converts its operands there, `a.toF64() / b.toF64()`, directly or through a `const` (decision 0034, d1, F113). `PERAS_PROTO_DIV=d0` builds the error as it was, for `scripts/bench-division.mjs` only. `Math` is written as in JavaScript, in both modes, `Math.f(x, …)` the method `f` of `x`, `Math.PI` and `Math.E` numbers; `floor`, `round`, `ceil` or `trunc` on an integer is E0215, its fix the removal, or, on an integer division, the division shown and divided as floats (decision 0035, a2 and b3; `Analysis::math_calls`). `PERAS_PROTO_MATH=a0` and `PERAS_PROTO_WHOLE=b0` build the errors as they were, for `scripts/bench-math.mjs` only. `PERAS_PROTO_NUM` builds the other options measured, for `scripts/bench-numbers.mjs` only.
- Integers: all eight compiled (decision 0024). JavaScript's values are wrapped to their type, `u32` and `u64` come back non-negative, `u64` as a `BigInt`. An `Array<u8>` is a byte an element; in an array of structures, such a field takes four bytes.
- A `String` parameter also takes a `Uint8Array` of UTF-8 bytes, checked, a leading byte order mark dropped (decision 0020, F217).
- Shared values: `Rc<T>`, read only and copied on write (decision 0032, r1): `Rc.new(v)`, a copy holds it once more, a write through a holder makes the value its own first (`shared_unique`); no cycle can be built. A `const` read from a place nothing changes or moves in the rest of the function is lent (`lent_shared`, `Analysis::mutations`). A write through an `Rc` held by another `Rc` or by an element makes each its holder's own where it is held (`unique_handle`, `shared_unique_slot`, `shared_unique_elem`). In a managed module, an `Rc` is a box `{ v, n }` counted, never released (decision 0033, m3): `$hold` where a holder is taken, `$own` before a write. `PERAS_PROTO_RC=r0` builds a compiler without `Rc`, for `scripts/bench-shared.mjs` only.
- Managed modules check each index where they read or write it, the check written out, `$at` and `$put` gone (decision 0037): the pond's managed module, built for production, at 1.14 to 1.19 times TypeScript's time. Build a managed module for production (`--allocator tlsf`) before comparing it with TypeScript (M029).
- JSON, in managed modules: `T.fromJson(text)` gives a `Result<T, String>` for a structure or an enumeration of the module, the error naming the path (`servers[0].port: …`); `x.toJson()` writes a structure, an enumeration or an array, a variant as its name or `{ "Name": [values] }` (decision 0038, j1). The reader of a type is made once (`$jsonReaders`); its path is built only for an error. An array is read through a structure that holds it. Not in owned modules yet: E0900.
- Pixels: a float's `roundEven()` rounds a half to the even in one instruction (`f64.nearest`), as a `Uint8ClampedArray` stores a number, in both modes (decision 0047, f3); `bench/frame/framebuffer-f3.peras` is a framebuffer of `u32` pixels written in Peras, free functions as the methods of an imported structure cannot be called. A frame drawn into an array the page made in the module (`__perasHeap.array`) is shown through its `view()`, no copy.
- Time: `Duration` and `Instant`, kinds of float the checker keeps apart (`FloatTy::Duration`, `FloatTy::Instant`), compiled as an `f64` of milliseconds in both modes, `Duration.ms(x)` being `x` (decision 0039, t1; `Analysis::time_calls`). `Duration.seconds(x)` and its kin make one, `d.toMs()` and its kin read it, `Instant.now()` is the page's clock in a managed module only; a number where a duration is meant is E0210, two instants added E0221, a number taken from an instant E0210 naming both (F225). `setTimeout` and `setInterval` wait a `Duration`.
- Tests: `test "name" { … }` blocks in the file they test, reaching its private functions; `expect(a).toBe(b)`, `.toEqual`, `.toBeOk()`, `.toBeErr()`, `assert`, `assertEqual`; run by Vitest through `vitest-peras`, which calls `perasc build --tests` (decision 0040, v2). Every parse blanks them out byte for byte (`perasc_syntax::testing::strip`), so a production build is unchanged and an error inside a test is seen only by the test build. A failure cannot show an array or a structure (F227).
- Formatting: `perasc fmt [--check] files…` prints each file at a width of 100, as Prettier prints TypeScript (decision 0041, f2; `perasc_syntax::format`, a Wadler printer over the tree of the tokens' brackets). Tokens, comments and the module built are kept, a second pass changes nothing, a syntax error leaves the file as it is (`format_corpus`, `scripts/bench-fmt.mjs --check`). Not yet run on the repository's own files, nor by the Vite plugin.
- Queries for the tools: `perasc serve`, a JSON request a line on standard input, an answer a line on standard output (decision 0042, q2; `crates/perasc/src/query.rs`, the protocol in `docs/en/reference/serve.md`). It keeps each file opened with its analysis, answers diagnostics, hover, definition, references, symbols, completion and format from it, and analyses again a file whose text, or an imported file's, changes: the driver reads an open text before the disk (`perasc_driver::set_open`). A file with a syntax error is analysed from the tree the parser recovers. The language server and the VS Code extension are proprietary, in `artkabis/peras-tools`, and use Peras only through `perasc` (decision 0006). Their state is documented here, in `docs/*/guide/editors.md`, what they do and their figures, never their code (the owner, 2026-11-24); update it when they change.
- Slow: adding to a large `Set` (F215), a key built per row only to be looked up (F202). Fast: `split`, sorts by a key, `get` then `set` of one key (F216).

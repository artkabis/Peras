# E0251 : Une fermeture qui capture ce qui peut changer

_Version anglaise, qui fait foi : [../../en/errors/E0251.md](../../en/errors/E0251.md)._

Dans un module owned (`.peras`), une fonction fléchée utilisée comme valeur copie ce qu’elle capture quand elle est faite, dans son environnement, qui ne change jamais ensuite ([décision 0026](../decisions/0026-closures.md)). JavaScript lit une variable capturée quand la fonction est appelée, si bien qu’une variable qui peut changer après que la fonction est faite donnerait un résultat dans un module owned et un autre dans un module managed. Un `let` et un paramètre `inout` peuvent changer : une fonction fléchée utilisée comme valeur ne peut pas les capturer. Un `const` et tout autre paramètre ne le peuvent pas, et sont capturés.

Une fonction fléchée donnée sur place, à `map` et aux autres, n’est pas une valeur : elle s’exécute là où elle est écrite, et lit un `let` tel qu’il est à ce moment.

## Exemple

```peras
fn apply(f: (i32) => i32, x: i32): i32 {
  return f(x);
}

export fn later(n: i32): i32 {
  let k = 1;
  const f = (x: i32): i32 => x + k;
  k = 100;
  return apply(f, n);
}
```

`f` capture `k`, un `let`. Un module managed donne `later(5) = 105`, la valeur de `k` quand `f` est appelée ; un module owned aurait copié `k` quand `f` a été faite.

## Correction

Capturer un `const` : copier la valeur voulue quand la fonction est faite, et le dire.

```peras
fn apply(f: (i32) => i32, x: i32): i32 {
  return f(x);
}

export fn later(n: i32): i32 {
  let k = 1;
  const start = k;
  const f = (x: i32): i32 => x + start;
  k = 100;
  return apply(f, n) + k;
}
```

Les deux modes donnent maintenant `later(5) = 106`.

# E0250 : Des modules qui s’importent l’un l’autre

_Version anglaise, qui fait foi : [../../en/errors/E0250.md](../../en/errors/E0250.md)._

Les modules owned (`.peras`) importent les fonctions, structures et énumérations les uns des autres, et un build les compile ensemble en un seul module WebAssembly ([décision 0022](../decisions/0022-owned-modules.md)). Chaque module est vérifié contre ce qu’exportent les modules qu’il importe, donc ceux-ci sont vérifiés d’abord. Un module qui dépend de lui-même, directement ou par d’autres, est refusé, avec le chemin du cycle.

## Exemple

`shapes.peras` importe `./units.peras` :

```peras
import { scale } from "./units.peras";

export struct Size {
  width: f64;
  height: f64;
}

export fn area(s: Size): f64 {
  return scale(s.width * s.height);
}
```

et `units.peras` importe `./shapes.peras` en retour :

```peras
import { Size } from "./shapes.peras";

export fn scale(x: f64): f64 {
  return x * 2.0;
}

export fn unit(): Size {
  return Size(1.0, 1.0);
}
```

Construire `shapes.peras` signale `shapes.peras → units.peras → shapes.peras`.

## Correction

Déplacez ce que les deux fichiers partagent dans un troisième, que chacun importe. Ici `Size` va dans `size.peras` :

```peras
export struct Size {
  width: f64;
  height: f64;
}
```

`units.peras` importe `Size` depuis `./size.peras`, et `shapes.peras` importe `Size` depuis `./size.peras` et `scale` depuis `./units.peras`. Les imports ne forment plus de cycle.

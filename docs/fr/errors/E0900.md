# E0900 : Pas encore pris en charge par la génération de code

_Version anglaise, qui fait foi : [../../en/errors/E0900.md](../../en/errors/E0900.md)._

Le programme est du Peras valide, accepté par toutes les vérifications, mais `perasc build` ne sait pas encore compiler l’une de ses constructions. Les codes `E0900` à `E0999` signalent des limites du compilateur, pas des erreurs du programme ; ils disparaissent au fur et à mesure que la génération de code s’étend.

Aujourd’hui, la génération de code traite tous les types entiers ([décision 0024](../decisions/0024-integer-types.md)), `f32`, `f64` et `bool`, les structures, les énumérations, les options, les résultats, les chaînes, les tables et les ensembles, et les tableaux de tous ces types, avec toutes les instructions (`for…of` compris), les appels, les paramètres `sink` et `inout`, et les méthodes marquées compilées dans la [référence des méthodes](../reference/methods.md). Les variables de module sont compilées quand elles tiennent des nombres, des booléens, et des structures, énumérations et options de ceux-ci ([décision 0023](../decisions/0023-module-variables.md)). Les fonctions sont des valeurs ([décision 0025](../decisions/0025-moved-fields-and-function-values.md)), mais une fonction fléchée qui capture une variable n’en est pas encore une (`closure`) : écris-la sur place, comme argument de `map` et des autres, ou passe ce qu’elle capture en paramètre. Les variables de module qui tiennent des chaînes ou des tableaux viennent ensuite ; la [page d’état](../reference/status.md) liste tout.

## Exemple

```peras
let prefix = "n";

export fn label(x: i32): i32 {
  return prefix.length + x;
}
```

## Correction

Réserve ce code à `perasc check` pour l’instant, ou limite le module compilé avec `perasc build` aux constructions prises en charge.

```peras
export fn label(prefix: String, x: i32): i32 {
  return prefix.length + x;
}
```

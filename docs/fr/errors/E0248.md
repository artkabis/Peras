# E0248 : Une promesse jamais attendue

_Version anglaise, qui fait foi : [../../en/errors/E0248.md](../../en/errors/E0248.md)._

Appeler une fonction `async` lance son travail et rend une promesse de son résultat. Sans `await`, les instructions qui suivent l’appel s’exécutent avant que ce travail soit fini, et une erreur qu’il lève est perdue. Oublier `await` est l’un des bugs les plus courants du code asynchrone ; le [banc des bugs d’applications web](../../../bench/README.fr.md#bugs-dapplications-web-benchweb-bugs) a trouvé que le linter de TypeScript l’attrapait là où Peras ne l’attrapait pas, jusqu’à cette vérification ([décision 0011](../decisions/0011-what-to-build-next.md)).

## Exemple

```apeiron
async fn save(): Promise<void> {
  await sleep(5);
}

export async fn submit(): Promise<String> {
  save();
  return "saved";
}
```

`"saved"` est rendu avant que l’enregistrement soit fini.

## Correction

```apeiron
async fn save(): Promise<void> {
  await sleep(5);
}

export async fn submit(): Promise<String> {
  await save();
  return "saved";
}
```

Pour laisser le travail tourner exprès, gardez sa promesse : `const _saving = save();`.

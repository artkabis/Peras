# Constats

_Version anglaise : [../en/findings.md](../en/findings.md)._

Ce que le travail sur Peras a appris, consigné tel qu’il a été trouvé : les bogues du compilateur, ce que le langage rend difficile à écrire, ce qu’il rend lent, ce qu’il ne sait pas encore faire, et les erreurs de méthode de ses propres études. Un langage se juge à la façon dont cela évolue avec le temps, pas à ses démos.

## Comment il est tenu

- **Chaque constat est consigné le jour où il est trouvé**, avec sa preuve : un diagnostic, une mesure, un commit, un test.
- **Rien n’est retiré.** Un constat corrigé reste, avec le commit qui l’a corrigé et le test ou la mesure qui le prouve ; un choix du langage dit pourquoi.
- **Il n’est fermé que par une preuve** : un test qui aurait échoué avant, ou une mesure sous un protocole. Une correction sans preuve reste ouverte.
- **Les erreurs de méthode comptent autant que les bogues** : une étude qui a mal compté, une affirmation faite avant d’être vérifiée. Ce sont elles qui rendent les autres chiffres dignes de confiance.

Compté à partir des entrées ci-dessous, le 2026-11-11.

Les bogues trouvés l’ont été avant de pouvoir être livrés : le vérificateur de libération a refusé le code (F001, F002), un test a échoué (F003), un banc s’est arrêté (F004). Ce qui reste ouvert, c’est ce que le langage coûte à écrire et à exécuter dans un vrai programme, trouvé en en écrivant un : le tableau de bord de la décision 0014.

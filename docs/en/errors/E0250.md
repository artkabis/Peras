# E0250: Modules that import each other

_French translation: [../../fr/errors/E0250.md](../../fr/errors/E0250.md)._

Owned modules (`.peras`) import each other's functions, structures and enumerations, and a build compiles them together into one WebAssembly module ([decision 0022](../decisions/0022-owned-modules.md)). Each module is checked against what the modules it imports export, so those are checked first. A module that depends on itself, directly or through others, is refused, with the path of the cycle.

## Example

`shapes.peras` imports `./units.peras`:

```peras
import { scale } from "./units.peras";

export struct Size {
  width: f64;
  height: f64;
}

export fn area(s: Size): f64 {
  return scale(s.width * s.height);
}
```

and `units.peras` imports `./shapes.peras` back:

```peras
import { Size } from "./shapes.peras";

export fn scale(x: f64): f64 {
  return x * 2.0;
}

export fn unit(): Size {
  return Size(1.0, 1.0);
}
```

Building `shapes.peras` reports `shapes.peras → units.peras → shapes.peras`.

## Fix

Move what both files share into a third, which each imports. Here `Size` goes to `size.peras`:

```peras
export struct Size {
  width: f64;
  height: f64;
}
```

`units.peras` imports `Size` from `./size.peras`, and `shapes.peras` imports `Size` from `./size.peras` and `scale` from `./units.peras`. The imports no longer form a cycle.

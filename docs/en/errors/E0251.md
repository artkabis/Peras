# E0251: A closure that captures what can change

_French translation: [../../fr/errors/E0251.md](../../fr/errors/E0251.md)._

In an owned module (`.peras`), an arrow function used as a value copies what it captures when it is made, into its environment, which never changes after ([decision 0026](../decisions/0026-closures.md)). JavaScript reads a captured variable when the function is called, so a variable that can change after the function is made would give one result in an owned module and another in a managed one. A `let` and an `inout` parameter can change: an arrow function used as a value cannot capture them. A `const` and any other parameter cannot, and are captured.

An arrow function given in place, to `map` and the others, is not a value: it runs where it is written, and reads a `let` as it is at that moment.

## Example

```peras
fn apply(f: (i32) => i32, x: i32): i32 {
  return f(x);
}

export fn later(n: i32): i32 {
  let k = 1;
  const f = (x: i32): i32 => x + k;
  k = 100;
  return apply(f, n);
}
```

`f` captures `k`, a `let`. A managed module gives `later(5) = 105`, the value `k` has when `f` is called; an owned module would have copied `k` when `f` was made.

## Fix

Capture a `const`: copy the value wanted when the function is made, and say so.

```peras
fn apply(f: (i32) => i32, x: i32): i32 {
  return f(x);
}

export fn later(n: i32): i32 {
  let k = 1;
  const start = k;
  const f = (x: i32): i32 => x + start;
  k = 100;
  return apply(f, n) + k;
}
```

Both modes now give `later(5) = 106`.

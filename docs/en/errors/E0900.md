# E0900: Not supported by code generation yet

_French translation: [../../fr/errors/E0900.md](../../fr/errors/E0900.md)._

The program is valid Peras, accepted by every check, but `perasc build` cannot compile one of its constructs yet. Codes `E0900` to `E0999` mark limits of the compiler, not mistakes in the program; they disappear as code generation grows.

Today, code generation handles every integer type ([decision 0024](../decisions/0024-integer-types.md)), `f32`, `f64` and `bool`, structures, enumerations, options, results, strings, maps and sets, and arrays of any of them, with every statement (`for…of` included), calls, `sink` and `inout` parameters, and the methods marked compiled in the [method reference](../reference/methods.md). Module variables are compiled when they hold numbers, booleans, and structures, enumerations and options of them ([decision 0023](../decisions/0023-module-variables.md)). Functions are values ([decision 0025](../decisions/0025-moved-fields-and-function-values.md)), and an arrow function that captures numbers or booleans is one too ([decision 0026](../decisions/0026-closures.md)); one that captures a string, an array, a map, a set or a function value is not yet (`closure-heap`): write it in place, as the argument of `map` and the others, or pass what it captures as a parameter. Module variables holding strings or arrays come next; the [status page](../reference/status.md) lists everything.

## Example

```peras
let prefix = "n";

export fn label(x: i32): i32 {
  return prefix.length + x;
}
```

## Fix

Keep such code to `perasc check` for now, or restrict the module compiled with `perasc build` to the supported constructs.

```peras
export fn label(prefix: String, x: i32): i32 {
  return prefix.length + x;
}
```
